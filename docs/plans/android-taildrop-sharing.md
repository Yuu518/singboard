# Android Taildrop 系统分享待定计划

## 原生轻量分享窗口

首次从相册或文件管理器选择「通过 Taildrop 发送」时，打开原生设备选择窗口。窗口只加载本次分享需要的文件和接收设备，跳过 Flutter 引擎与 Singboard 主页。应用进程已被回收时，由 Android 启动承载分享入口的进程。

沿用现有的分享文件读取授权、批次队列和 Rust 上传逻辑。后台任务接管文件后即可关闭窗口，回到来源应用。通知栏提供进度和取消操作，传输结束后释放任务。

## 在系统分享面板快速选择上次的设备

首次选中设备并成功发送后，通过 Android Sharing Shortcuts 把该设备发布为系统分享目标。例如，第一次把照片发给「书房电脑」，下次在相册点分享时，就有机会直接点「书房电脑」。此时打开该设备的发送窗口，列出本次文件，点「发送」即可，无需再选设备。

快捷目标绑定到原后端、Service API 服务、Tailscale 端点和设备的 `stableId`，名称仅用于展示。同一设备改名时更新名称。设备失去接收资格或所属配置被移除时撤下快捷目标。若用户点到系统缓存的失效入口，保留本次分享内容，提示重新选择设备。

系统决定推荐行的排序和展示。若系统未展示快捷目标，普通「通过 Taildrop 发送」入口应预选仍可接收的上次设备，允许更换。最近设备功能可先接入现有分享窗口，也可与原生窗口一起交付。[Android Direct Share 文档](https://developer.android.com/develop/ui/compose/sharing/direct-share-targets)

## 验收场景

- 结束 Singboard 进程后从相册分享，直接看到原生选择窗口。后台接管后回到相册，仍可从通知栏查看或取消传输。
- 成功分享给同一台电脑后，从另一应用分享多个文件。点击系统推荐的设备，直接确认该批文件与目标设备。
- 系统未推荐设备时，普通入口预选上次的有效设备。移除原设备后，即使另一台设备同名，也须由用户重新选择。
